# CLI Shell Interpreter (C++)

Простой интерпретатор командной строки с поддержкой пайплайнов,
переменных окружения и встроенных команд.

## Текущий статус реализации 

### Реализовано:
- Read–Execute–Print Loop (REPL)
- встроенные команды: cat, echo, wc, pwd, **grep**, exit
- поддержка одинарных и двойных кавычек
- assignment-only переменные окружения (NAME=VALUE)
- запуск внешних программ
- передача переменных окружения внешнему процессу
- поддержка stdout, stderr и exit code
- кроссплатформенная сборка (Linux, macOS, Windows)
- юнит-тесты и CI

### Пока не реализовано (запланировано):
- редиректы ввода/вывода


## Возможности (HW-02)

## Дополнительные возможности (после HW-03)

## ### 1. Подстановка переменных ($VAR и ${VAR})

Реализована полная поддержка подстановки переменных окружения:

- **$VAR** - простая подстановка переменной
- **${VAR}** - подстановка с фигурными скобками (позволяет использовать переменные в составных выражениях)
- **Различие в кавычках**:
  - В одинарных кавычках (`'...'`) подстановка НЕ происходит
  - В двойных кавычках (`"..."`) подстановка происходит

Примеры:
```bash
> FOO=hello
> echo $FOO
hello
> echo "$FOO world"
hello world
> echo '$FOO'
$FOO
> echo ${FOO}_test
hello_test
```

### 2. Пайплайны (|)

Реализована поддержка пайплайнов для передачи вывода одной команды на вход другой:

- Поддерживается произвольное количество команд в пайплайне
- Символ `|` является специальным разделителем
- Корректная обработка stdin/stdout через pipes
- Поддержка как встроенных, так и внешних команд в пайплайне

Примеры:
```bash
> echo "hello world" | wc
1 2 12
> cat file.txt | wc
> ls | cat | wc
```

### 3. Улучшенная обработка ошибок

- Проверка на пустые команды до и после `|`
- Корректные сообщения об ошибках
- Shell никогда не падает из-за некорректного пользовательского ввода

### 4. Встроенная команда grep (CLI-3)

Поддерживаются:
- **Регулярные выражения** в запросе (ECMAScript-синтаксис).
- **-w** — поиск только целого слова (граница слова = не буква/цифра/подчёркивание; буквы по стандартной библиотеке C++).
- **-i** — регистронезависимый поиск.
- **-A N** — печатать N строк после совпадения (включая строку совпадения); при пересечении областей каждая строка выводится один раз.

Разбор аргументов grep выполняется библиотекой **CLI11** (см. ниже).

Минимальный синтаксис grep:
```bash
shell> grep "Минимальный" README.md # это пример из README.md
shell> grep -i "минимальный" README.md # регистронезависимый поиск
shell> grep -w "Минимал" README.md # поиск только целого слова
shell> grep -A 1 "II" README.md # печатать 1 строку после совпадения
```

#### Выбор библиотеки для разбора аргументов командной строки (grep)

Требование: не парсить аргументы grep вручную; использовать одну из библиотек для разбора CLI.

**Рассматривались (C++):**
- **CLI11** — header-only, C++11+, активная разработка, простой API, не требует Boost.
- **cxxopts** — header-only, похожий по идее, менее богатый функционал.
- **Boost.Program_options** — тяжёлая зависимость (весь Boost или значительная часть).
- **Lyra** — минималистичная, меньше возможностей для позиционных аргументов и проверок.

**Выбор: CLI11.**  
Причины: header-only (подключается через FetchContent, одна цель CMake), не тянет Boost, удобный API для флагов и позиционных аргументов (pattern + files), хорошая документация и сообщество. Подходит для учебного проекта по критерию «минимальные затраты и простота интеграции».

**Лицензия CLI11:** проект использует библиотеку [CLI11](https://github.com/CLIUtils/CLI11) (BSD-3-Clause). Текст лицензии и копирайт сохранены в [licenses/CLI11](licenses/CLI11).

## Архитектура

Проект реализуется как модульный интерпретатор командной строки.  
Архитектура разделена на независимые компоненты с чёткой ответственностью.

Основные подсистемы:

- **Shell / REPL** — точка входа, цикл чтения команд, хранение окружения и кодов возврата.
- **Frontend** — фасад для анализа ввода.
  - **Lexer** — разбор строки на токены с учётом кавычек и `$`-подстановок.
  - **Parser** — построение AST (Pipeline / CommandSpec).
- **Executor** — выполнение команд и пайплайнов, работа с `fork/exec/pipe/dup2/wait`.
- **BuiltinRegistry** — встроенные команды (`echo`, `cat`, `wc`, `pwd`, `grep`, `exit`). Для `grep` разбор опций выполняется модулем Grep с использованием CLI11.
- **ExternalRunner** — запуск внешних программ через `execve` и поиск в `PATH`.
- **Environment** — хранение и модификация переменных окружения.

Архитектура проектируется заранее и может уточняться в процессе реализации,
однако основные интерфейсы и ответственность компонентов фиксированы.

Полное описание архитектуры и диаграммы:

## Сборка и запуск

### Linux / macOS

**Сборка:**
```bash
cmake -S . -B build -DCLI_BUILD_TESTS=ON
cmake --build build
```

**Запуск:**
```bash
./build/shell
```

**Тесты:**
```bash
ctest --test-dir build --output-on-failure
```

### Windows (Visual Studio / MSVC)

**Сборка:**
```powershell
cmake -S . -B build -DCLI_BUILD_TESTS=ON
cmake --build build --config Release
```

**Запуск (обычно):**
```powershell
.\build\Release\shell.exe
```

**Тесты:**
```powershell
ctest --test-dir build -C Release --output-on-failure
```
